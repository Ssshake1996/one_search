# one_search 实施与验收路线图

目标是在普通电脑/服务器上持续发现文件和授权数据库内容，通过 MCP 返回可定位的证据，优先控制后台资源。顺序保持为：先完成单机，再验证更大真实规模与不同硬件，最后实施和验收多机。v0.2 已实现此前确认的六项优化；尚未执行的硬件和规模验收不写成完成。

## 状态的含义

- **已实现**：代码和对应接口已落盘，并有针对性验证；不等于所有平台/规模均通过。
- **已执行验证**：有实际命令、环境和结果记录。精确测试计数、基准及发行一致性以 [验证报告](../VALIDATION.md) 为准。
- **待验收**：实现可用，但目标硬件、真实数据量或使用场景尚未实际执行。
- **待实现**：仍需要功能代码、协议设计及测试。

## 阶段一：单机产品与六项优化——已实现

| 项目 | 当前交付 | 已有证据 / 尚存边界 |
|---|---|---|
| 单机文件/MCP闭环 | 文件名、正文、语义、混合检索；共享后台与五个 MCP 工具 | Windows、合成文件、真实本地模型与官方 MCP SDK 已执行；完整格式范围见 [FORMATS](../FORMATS.md) |
| 本机范围发现 | 新安装默认当前用户可访问的本地磁盘；可切换目录，旧范围不扩大 | [范围测试](../../tests/test_scope.py)；当前不是 NTFS MFT/USN 引擎，不声称已经扫描并验收整台用户电脑 |
| 1. 分层索引 | 文件名、正文、语义分层；正文/语义支持目录、扩展名、关闭 | [Engine 测试](../../tests/test_engine.py)；默认全范围解析仍需较长首建时间 |
| 2. 存储优化 | float16 持久化向量、external-content FTS5、旧向量兼容与离线 compact | Store/Engine 回归；总体节省比例依实际文本、向量和旧索引分布，不预填提升数字 |
| 3. ANN 后台发布 | 隔离 worker 建立不可变快照，完整后原子发布，旧版可查询 | [向量测试](../../tests/test_vectors.py)；没有旧版时返回 pending，不能编造可用语义结果 |
| 4. 候选和证据读取 | 过滤/去重不足时扩大候选，上限 8,192，批量读取证据 | Engine 过滤回归；有界 ANN 仍非穷尽召回，达到上限有提示 |
| 5. 数据库持续同步 | Keyset 分页、持久化进度、水位增量、完整巡检与分批删除 | SQLite 1,127 行及真实 MySQL 8.4.11/PostgreSQL 17.11；[本轮数据库报告](../validation/databases-v0.2.json)；非 CDC |
| 6. 资源控制 | Windows Job、低优先级/亲和性、数值库线程限制，RSS/磁盘预算和回退状态 | [资源测试](../../tests/test_resources.py)；Job 内存是 committed virtual memory，不是 RSS；Linux 无硬配额 |
| 安装与设置 | Windows 自带运行时包、Python bootstrap、本地 GUI、服务生命周期 | 原生模型/查询/MCP和隔离安装已执行；最终包校验与详细结果以主报告为准；宿主插件商店钩子未验收 |

六项优化已经进入当前代码。后续按真实使用边界验收，根据测量结果修正，并记录有依据的性能结论。

## 阶段二：8GB/16GB 与几百 GB 资料——待验收

在独立测试账户/设备、明确同意的资料范围内执行；优先使用去标识的代表性资料，记录操作系统、CPU、物理内存、SSD/HDD、源文件数/类型、实际可提取文字量与片段数。数据目录标称“500GB 磁盘”不能替代这些输入。

| 验收项 | 执行方法 | 完成判据 |
|---|---|---|
| 8GB 家庭电脑 | 分别验证文件名、指定目录正文、精选语义，再提高覆盖 | 安装/检索/暂停/恢复/退出闭环；记录 RSS、commit、CPU、磁盘和交互影响；预算触发可见且能够恢复 |
| 16GB 电脑 | 在相同语料与问题集上重复 | 给出同口径记录，区分暖/冷查询和建库并发，不能用另一台 32GB 机器模拟结果代替 |
| 数百 GB 真实资料 | 分清文件名元数据、支持正文、语义片段量；分阶段建立索引 | 覆盖、失败和排除项可核对；测首建/增量/删除耗时与空间；重启、暂停、断电后能恢复 |
| 查询体验 | 固定问题集，分文件名/关键词/语义/混合；区分冷启动、暖缓存、索引中查询 | 发布中位数与尾延迟、结果质量、当前候选/范围限制；不把纯查询内核基准当作整机响应承诺 |
| 大数据库 | 业务方只读账户与必要索引，跨多个 tick、更新/删除/回填/连接中断 | 全表覆盖可核对、断点恢复、无错误删除；记录源库负载；未维护水位的限制明确 |
| 长时间运行 | 连续后台更新、源文件变化、低磁盘/内存压力 | 无持续资源泄漏、失控重试或不可恢复索引状态，日志及错误可定位 |

验收前固定版本、配置、语料和问题集。出现资源或质量问题时先修复并重跑受影响项；没有执行的结果保持“待验收”。

## 阶段四：多机——接口已预留，功能待实现

当前仅接受本节点 `node_id`，不绑定外网地址；请求其他节点会明确返回尚未实现。多机不能靠把本机端口直接开放来视作完成。

后续实施内容：节点注册与发现、节点身份与 TLS、远程范围/账号授权、连接和断线重试、跨节点查询扇出与结果合并、部分节点失败提示、证据定位及撤销语义。保留 `(node_id, source_id, id)`，避免本地 ID 冲突。

验收至少包括两台真实机器：分别授权并建库、联合查询、来源标记、断线后部分结果提示、重连恢复、权限撤销即时生效、更新/删除可核对。单机测试通过不将这一阶段标记完成。

## 交付与追踪

每次版本交付应包含：可安装包及平台/运行时要求、源码/产物校验、安装/卸载/升级结果、测试与质量报告、实际基准和已知限制。项目入口为 [README](../../README.md)，使用说明为 [INSTALL](../INSTALL.md)，实现约定为 [CONTRACTS](../CONTRACTS.md)。精确测试计数、性能数据和变化历史分别以主验证报告与发布说明为准，避免在多份路线图中维护互相冲突的数字。
