# one_search 实施与验收路线图

目标是在普通电脑/服务器上持续发现文件和授权数据库内容，通过 MCP 返回可定位的证据，优先控制后台资源。顺序保持为：先完成单机，再验证更大真实规模与不同硬件，最后实施和验收多机。v0.4 已实现用户确认的单机产品路径；尚未执行的硬件和规模验收不写成完成。

## 当前版本：v0.4 产品路径

完整交付矩阵见 [v0.4 目标与验收](PRODUCT-v0.4.md)，实测与发行记录以 [验证报告](../VALIDATION.md) 为准。

| 路径 | 当前实现 |
|---|---|
| Agent 安装与接入 | README 权威入口、幂等安装、基础能力先可用、异步模型、离线导入、取消与重试、DSH profile 接入验证 |
| 找到并核实资料 | 组合筛选、精确文件名、上下文、来源引用、重复正文折叠与版本边界 |
| 解释漏检与更新 | 指定路径诊断、优先处理、单文件刷新、过期/替换/撤权与旧引用拒绝 |
| 调整范围和资源 | 三层范围与排除、敏感模板、影响预览、三档预算、定时暂停和自动退让 |
| 数据库接入 | 连接→发现→表列选择→键/水位建议→只读预检，系统凭据、业务别名与错误恢复 |
| 日常维护与退出 | 版本兼容、空间分类、配置导出恢复、索引迁移、备份清理、共享宿主影响、升级回滚与卸载 |
| 验收 | 当前 Windows、合成数据、实际 DSH 问答与数据库已有记录；物理低内存、大语料和长期稳定性仍须单独验收 |

下面的阶段一和八项优化是 v0.2/v0.3 历史基础；当前 MCP 为 11 个工具。后续阶段保留真实环境验收和多机实现，不反复重做已交付功能。

## 状态的含义

- **已实现**：代码和对应接口已落盘，并有针对性验证；不等于所有平台/规模均通过。
- **已执行验证**：有实际命令、环境和结果记录。精确测试计数、基准及发行一致性以 [验证报告](../VALIDATION.md) 为准。
- **待验收**：实现可用，但目标硬件、真实数据量或使用场景尚未实际执行。
- **待实现**：仍需要功能代码、协议设计及测试。

## 阶段二：8GB/16GB 与几百 GB 资料——待验收

在独立测试账户/设备、明确同意的资料范围内执行；优先使用去标识的代表性资料，记录操作系统、CPU、物理内存、SSD/HDD、源文件数/类型、实际可提取文字量与片段数。数据目录标称“500GB 磁盘”不能替代这些输入。

| 验收项 | 执行方法 | 完成判据 |
|---|---|---|
| 8GB 家庭电脑 | 分别验证文件名、指定目录正文、精选语义，再提高覆盖 | 安装/检索/暂停/恢复/退出闭环；记录 RSS、commit、CPU、磁盘和交互影响；预算触发可见且能够恢复 |
| 16GB 电脑 | 在相同语料与问题集上重复 | 给出同口径记录，区分暖/冷查询和建库并发，不能用另一台 32GB 机器模拟结果代替 |
| 数百 GB 真实资料 | 分清文件名元数据、支持正文、语义片段量；分阶段建立索引 | 覆盖、失败和排除项可核对；测首建/增量/删除耗时与空间；重启、暂停、断电后能恢复 |
| 查询体验 | 固定问题集，分文件名/关键词/语义/混合；区分冷启动、暖缓存、索引中查询 | 发布中位数与尾延迟、结果质量、当前候选/范围限制；不把纯查询内核基准当作整机响应承诺 |
| 大数据库 | 业务方只读账户与必要索引，跨多个 tick、更新/删除/回填/连接中断 | 全表覆盖可核对、断点恢复、无错误删除；记录源库负载；未维护水位的限制明确 |
| 长时间运行 | 连续后台更新、源文件变化、低磁盘/内存压力 | 无持续资源泄漏、失控重试或不可恢复索引状态，日志及错误可定位 |

验收前固定版本、配置、语料和问题集。出现资源或质量问题时先修复并重跑受影响项；没有执行的结果保持“待验收”。

## 阶段四：多机——接口已预留，功能待实现

当前仅接受本节点 `node_id`，不绑定外网地址；请求其他节点会明确返回尚未实现。多机不能靠把本机端口直接开放来视作完成。

后续实施内容：节点注册与发现、节点身份与 TLS、远程范围/账号授权、连接和断线重试、跨节点查询扇出与结果合并、部分节点失败提示、证据定位及撤销语义。保留 `(node_id, source_id, id)`，避免本地 ID 冲突。

验收至少包括两台真实机器：分别授权并建库、联合查询、来源标记、断线后部分结果提示、重连恢复、权限撤销即时生效、更新/删除可核对。单机测试通过不将这一阶段标记完成。
