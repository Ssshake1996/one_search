# v0.5.2 暂停、连接诊断与文档目录默认范围验证

本轮修复包含常驻暂停控件、在途后台任务取消、具体连接错误码，以及首次安装默认文档目录。用户报告的故障位于另一台电脑/服务器，未取得该实例日志；以下证据不能证明远端故障的具体原因或所有连接失败都已消除。

## 代码与进程验证

- [本机回归记录](validation/tests-v0.5.2.json)：Windows 完整 Python 回归 556 通过、5 跳过；版本元数据更新后的相关回归 67 通过；最终 Node 回归 75 通过。跳过项为 Linux 专属回退及未配置的真实 MySQL/PostgreSQL 服务验收，不能算作通过。
- 后台新增测试使用真实 CPU 子进程复现解析、数据库请求和语义编码在途任务。修复前暂停后仍在运行；修复后取消且待处理工作保留，不累积失败退避。语义测试替代了推理负载，未验证实际模型质量或大规模内存表现。
- 临时目录与真实 SQLite/daemon 验证：暂停期间新增文件/数据库行不进入索引、已有内容可查询、服务重启保留暂停、恢复后继续；数据库页中途暂停后的游标回放完整。
- Web bridge 使用真实 HTTP 测试服务注入拒绝连接、超时、断线、401、503、无效/超大响应等故障，核对错误码/建议且不泄露凭据。服务身份变更只重试一次只读状态；写操作不重放。
- Windows 文档目录通过 Known Folder API 只读核对，并与系统 Documents 路径一致，未扫描用户资料；XDG、本地化目录、不可用目录与旧配置保留有回归测试。

[GitHub Actions 36449753922](https://github.com/Ssshake1996/one_search/actions/runs/36449753922) 的 Windows 与 Ubuntu 任务均通过：[CI 记录](validation/ci-v0.5.2.json)对应源码提交 `60dcd7d`，Windows Python 555 通过/6 跳过，Ubuntu 524 通过/37 跳过，两个平台 Node 回归均通过。Ubuntu 另完成真实无界面安装、暂停期间显式刷新、重装保留配置、索引迁移和卸载清理流程；未验证自启动及语义模型。平台计数分别报告，不合并为同一轮结果。

[真实浏览器 React fixture](validation/web-controls-v0.5.2.json) 验证了桌面 1280×900 和窄屏 375×812：所有页签均可暂停/恢复，离线展示错误码/建议和禁用状态，恢复及重试可用，控制台无错误。后台响应为明确标记的模拟数据，不等同于完整 DSH 宿主实测。

[候选发行包实际验收](validation/release-v0.5.2.json) 使用最终代码、独立合成目录、`-SkipModel -NoAutostart`：

上述时间只描述此机与合成小目录，不能外推几百 GB 首次建索引或家庭电脑性能。验收完成后只停止本轮建立的两个服务，没有修改用户原安装。完整 DSH profile/browser 集成与语义模型下载/检索未包含在本轮包验收中。

候选包验收后仅补入公开验证文档；最终归档再次核对全部文件校验和、完整插件文件集，以及已验收运行时、wheel、安装器和插件代码字节不变。GitHub 上传后的 SHA-256 再与本地产物核对，最终压缩包摘要以 Release 的 `SHA256SUMS.txt` 为准。

## 验证边界

8GB/16GB 实机、数百 GB 真实资料、远程 DSH 部署和多机传输未在本轮验证。没有新增聊天模型回答质量验收；没有声称暂停会取消独立模型下载或用户显式查询/刷新。

v0.5.1 的原生升级、多 DSH profile、回滚和断电恢复证据保留于 [上一版验证报告](VALIDATION-v0.5.1.md)。这些是上一版本记录，本轮不重复宣称为新包的完整升级验收。
