# 单机验证报告 · 0.1.0

日期：2026-09-25。结论：文件/数据库检索、本地语义、共享后台服务、MCP 与 Windows 安装流程已完成单机闭环，可进入选定真实目录的小范围试用。尚不能宣布几百 GB 正文、8GB 物理机或跨机环境已通过验收。

## 环境与功能

本机 Windows 11（内核 10.0.22631）、Python 3.11.3、i7-13700、16 个物理核/24 个逻辑核、约 31.8 GiB 内存。基准未单独核实磁盘型号/介质类型。没有读取实际业务数据库，也没有把用户全盘纳入索引。

最终测试：`python -m pytest -q`，**134 passed, 2 skipped，17.04 秒**。两个 skipped 是需要显式专用服务端配置的 MySQL/PostgreSQL 测试；它们此前已在本机启动的真实临时数据库中单独跑过：包含 SQLite 的数据库测试组 **42 passed，1.19 秒**，MySQL **8.4.11**、PostgreSQL **17.11**。这两个耗时都不含安装数据库、下载依赖或生成样本；原始版本记录见 [databases.json](validation/databases.json)。

## 检索质量

资料为 16 个合成文件、SQLite 四张表的 8 条记录；当前切片后共 87 个片段。共 35 个固定问题：22 语义、5 关键词、1 文件名、4 无答案、3 数据库。原始结果见 [quality.json](validation/quality.json)。

| 样例 | 实测 |
|---|---|
| 22 个语义问题 | 文件级 Recall@5：21/22（95.45%）；Recall@10：22/22 |
| 其中中文 | 19/19 在前 5 条找到目标文件 |
| 英文 | 2/2 在前 5 条找到目标文件 |
| 跨语言 | 1 条中文问英文材料，目标排第 8，未进前 5 |
| 关键词 / 文件名 | 5/5、1/1 在前 5 条找到目标文件 |
| 精确数据库查询 | 3/3，包含不存在订单应返回零行 |

这些是文件召回率，**不是回答正确率**。返回片段和定位随报告保留，需结合原文判断证据。四个无答案问题只记录近邻与 evidence-only 标识，没有使用聊天模型测试回答层；不能据此声称已经解决幻觉。中英跨语言检索仍是这个小中文模型的薄弱项。

## 资源实测

由外部采样器只统计 daemon 及其所有后代进程，间隔 100ms。使用上述小样本，预算 1,024 MiB，模型 1 线程、批量 8。详见 [resources.json](validation/resources.json)。

| 阶段 | RSS |
|---|---:|
| 初次索引采样峰值 | 255.68 MiB |
| 模型热查询采样峰值 | 193.75 MiB |
| 模型释放后静置 10 秒平均 / 峰值 | 43.38 / 43.38 MiB |
| 数据目录加外部模型 | 约 26.4 MiB |

20 次小样本热语义查询，包含 loopback RPC，P95 **49.53ms**。该数字仅对应 87 个片段。测试把模型闲置释放设为 2 秒以缩短等待，产品默认 120 秒。CPU 时间在静置窗口内没有可见增量；不意味着永远零 CPU。

RSS 求和可能重复计算共享页面，100ms 采样可能遗漏短暂峰值；未计 DSH、MCP 桥、系统缓存及其他应用。32GB 实机上限制预算为 1GB，不等于已经在 8GB 实机测试。实际源文件越复杂、片段越多，索引和模型外的占用也会增加。

## 10 万条索引基准

10 万文档记录、10 万正文片段，正文共 **27,026,395 字节（约 27MB）**。路径为合成字符串，没有创建 10 万个真实文件；向量是有固定随机种子的 512 维合成数据。每类 200 次暖查询。详见 [benchmark.json](validation/benchmark.json)。

| 项目 | P50 | P95 |
|---|---:|---:|
| 文件名 SQL 查询内核 | 0.853ms | 2.110ms |
| FTS5 关键词候选查询 | 88.515ms | 90.763ms |
| 合成向量 ANN 查询 | 2.964ms | 3.757ms |

边界：文件名测量不含真实文件权限/过期检查；关键词不含候选后的证据组装；ANN 不含模型编码、检索质量、原文读取。三者均不含 MCP、聊天回答、冷启动和初次文件读取。不能将 ANN 的 3.757ms 写成完整语义检索时间，也不能将内核结果当作原先完整端到端 P95 目标已经通过。

- 文本和合成向量入库：15.208 秒。
- 首次 ANN 构建：646.102 秒，约 10 分 46 秒。
- 1,000 新增 + 1,000 删除：源索引更新 0.632 秒、ANN 增量同步 7.842 秒，未全量重建。
- 整个基准过程峰值 RSS：195.87 MiB；最终索引：722.78 MiB。

真实首次索引还需文件枚举、解码、解析、模型计算及节流，耗时可能明显增加。27MB 的这组短文档就需要约 723MiB 索引，也说明向量/倒排索引空间不能按源盘容量简单估计。默认磁盘预算到达后会停止继续扩展并报告，不能承诺把几百 GB 正文全部装进 10GB 索引。

## 复现入口

在开发环境安装 `.[dev]`，使用新目录避免复用已有索引影响首次建库测量：

```powershell
python -m pytest -q
python scripts/create_demo.py --output .demo-new
python scripts/evaluate_search.py --demo .demo-new --model <已下载的模型目录> --data .runtime/quality-new --output docs/validation/quality.json
python scripts/benchmark_search.py --output .bench-new --documents 100000 --report docs/validation/benchmark.json
python scripts/measure_resources.py --model-dir <已下载的模型目录> --output docs/validation/resources.json
```

资源脚本参数以 `--help` 为准；外部数据库集成测试只在显式配置 `DATA_SEARCH_TEST_MYSQL_CONFIG` / `DATA_SEARCH_TEST_POSTGRES_CONFIG` 后启用。禁止把正式业务库当测试写入目标。

## 尚未验证与首版限制

Linux 安装及 systemd 生命周期、PostgreSQL 16/18、真实 TLS/VPN/SSH、8GB/16GB 实机、真实几百 GB 资料、百万片段长期负载、多用户隔离和真实多机网络接入尚未验证。没有交付内置 Python 的原生安装器，也未验证 DSH 插件商店安装钩子；当前是统一安装脚本安装后台，再导入生成的 MCP 配置。

文件正文默认最多 32MiB/200 万字符，数据库正文默认每个源最多 1,000 条有界快照。数据库变更通过有界快照哈希比对，未实现 CDC 或自动遍历无限大数据集。语义结果过滤基于有限候选，可能漏召回。正文刷新 3 分钟是调度间隔，不能保证积压情况下 3 分钟内全部处理完。

多机只保留接口协议，本轮未启动远程节点、开启远程监听或实现跨节点聚合。下一轮可在本机真实目录样本通过后，再验证传输、鉴权、节点生命周期与合并排序。
