# 文件与演示资料范围

文件名搜索与正文搜索是两项能力。授权目录内可枚举的文件，即使正文格式不支持，也保留文件名、路径及元数据。正文只对成功解析的范围建立索引；结果中的状态和原因必须展示，不能把未解析误报为没有相关内容。

## 已实现的正文提取

| 类别 | 格式 | 内容 | 定位 |
|---|---|---|---|
| 文本与代码 | TXT、MD、MARKDOWN、LOG；Python、JS/TS、Java、Go、Rust、C/C++、C#、Shell、PowerShell、SQL、CSS，以及模块中列出的常见文本扩展名 | 原始文本与注释，不执行代码 | 起止行号 |
| 配置和结构化文本 | JSON、JSONL、YAML/YML、TOML、INI、XML、CONF、CONFIG、PROPERTIES、ENV 等 | 原始字段和内容；XML 配置按文字处理 | 起止行号 |
| 本地 HTML | HTML、HTM | 文件内的可提取文字；忽略 script、style、template、noscript 内容，不执行脚本，不访问外链 | 原文件行号 |
| 文本表格 | CSV、TSV | 表头、单元格文字；支持带引号的多行字段 | 逻辑记录编号、列范围 |
| Word | DOCX | 正文段落、表格文字 | 段落序号，表格内容附表格序号 |
| Excel | XLSX | 工作表名、单元格内容、公式和已有缓存结果；常见日期按 ISO 文本表示 | 工作表名、单元格引用 |
| PowerPoint | PPTX | 幻灯片文字、表格文字、演讲备注 | 幻灯片编号、是否备注 |
| PDF | PDF 中可提取的文字层 | 页面文字 | 从 1 开始的页码 |

文本支持 UTF-8、带 BOM 的 UTF-8/UTF-16/UTF-32，以及 GB18030；无 BOM 的 UTF-16 仅进行有限识别。不能可靠解码或含明显二进制控制字符时报告错误。文本自动识别不等于支持全部历史编码。

提取器每个片段最多 1,200 个字符；服务将定位相同的相邻短片段合并为上下文，再切成最多 350 字符、重叠 50 字符的检索片段。一个长段落的片段共享段落定位并附字符偏移；行号定位属于提取片段范围。不为 DOCX 编造页码，不把 CSV 的多行字段当成多个记录。

## 明确边界

- DOC、XLS、PPT、ODF、RTF、EPUB、CAD、图片、音视频和压缩包内部内容，首版不提取正文。压缩包本身仍可以按文件名搜索。
- 扫描 PDF 和文档内图片不做 OCR。完全没有可提取文字的 PDF 返回 `unsupported`；混合 PDF 返回可提取文字，并报告没有文字的页面数量。空白页和扫描页不能仅凭没有文字区分。
- DOCX 仅承诺正文和表格；页眉、页脚、脚注、批注、文本框及嵌入对象未列入验收范围。复杂布局可能与视觉阅读顺序不同。
- XLSX 不执行宏、不重算公式、不刷新外部连接。公式缓存可能缺失或陈旧；缺失时明确标记，不能把它解释为零。常见共享公式展开为单元格公式，但不保证所有 Excel 公式扩展和格式显示效果。
- PPTX 不提取图片文字、图表渲染内容或嵌入对象。备注中的页码、日期等模板占位符会被排除。
- HTML 不渲染 CSS，不运行 JavaScript。JS 动态生成的文字不存在于本地 HTML 时无法提取；CSS 隐藏但存在于正文的文字仍可能被索引。
- PDF 复杂表格、分栏和字体编码的阅读顺序与字符恢复效果取决于解析库。加密 PDF 报告 `encrypted`，不尝试破解或绕过密码。
- 加密 OOXML 依据容器和加密流标记识别；真实密码保护 Office 样本尚未完整验证。格式错误或无法确认的容器可能报告 `error`。
- 云盘占位文件需要先下载到节点。外部关系引用不访问；原始数据库存储文件不能当成办公文档读取。

## 资源限制与状态

服务先限制源文件大小，再在单独进程中约束提取的时间和内存。提取器另设字符上限、输入读取上限、最多 20,000 个片段、OOXML 成员数量和解压总量限制。CSV 单条记录也受独立预算约束，避免巨大字段绕过限制。

| 状态 | 含义 |
|---|---|
| `ready` | 在支持范围内完成提取；仍需查看可能的格式提示 |
| `partial` | 字符、片段数量、输入量或解压预算限制导致未完整提取，`truncated=true` 并提供原因 |
| `unsupported` | 格式不支持，或 PDF 无可提取文字且未启用 OCR |
| `encrypted` | 已识别密码保护 |
| `error` | 文件损坏、编码错误、缺少依赖或其他解析错误 |

`partial` 可能有部分片段，也可能没有片段，例如 OOXML 解压总量预检即超过预算。服务层另有 `pending`、`budget` 状态。PDF/OOXML 解析内部可能先分配内存；服务保留约 100ms 的进程树 RSS 采样和终止子进程机制；Windows 另尝试为每个 worker 应用 Job 内存限制，其指标是提交虚拟内存（committed virtual memory），不是 RSS。限制是否生效及策略回退可从 `worker_controls` 查看。Linux 当前只有软调度/亲和性与采样预算，未实现 cgroup 硬限额。采样间隔内的 RSS 峰值与系统文件缓存仍不由预算严格保证；超时或资源不足会明确报告。

## 创建可试用的合成资料

在已安装项目及开发依赖的环境执行：

```powershell
python scripts/create_demo.py --output C:\Temp\data-search-demo
```

Linux 也可使用：

```sh
python scripts/create_demo.py --output /tmp/data-search-demo
```

输出目录必须为新目录或空目录；已有文件时拒绝覆盖。生成器只写合成资料，不读取用户文件、不连接网络、不自动启动服务。

输出包括：

- `files/`：16 个中英文文本、代码、配置、HTML、CSV/TSV、DOCX、XLSX、PPTX、PDF 文档，覆盖服务器降本、容量故障、订单退货、入职休假和项目计划。
- `databases/demo.sqlite`：四张小表 `orders`、`employees`、`support_tickets`、`projects`，所有人员和业务记录均为演示数据。
- `database_config.json`：一个可加入主配置 `databases` 数组的 SQLite 数据源对象，已配置表、字段白名单和文本索引字段。
- `demo_manifest.json`：源文件列表、校验值、明确的文件根目录和数据库配置位置。

文件索引根目录应选择生成结果的 `files/`，SQLite 通过数据库适配器连接。不要把演示输出目录的元数据清单和参考问题一起纳入文件索引，否则会污染质量评估。

生成器依赖项目已有的 Office 库，以及开发依赖 `reportlab`。演示工作簿特意包含没有缓存值的合计公式，用于验证系统不私自重算。

## 检索质量样本

`tests/evaluation_queries.json` 提供 35 题：22 条语义问题（含英文和跨语言）、5 条精确关键词、1 条文件名、4 条无答案问题和 3 条数据库查询。期望文件路径相对演示输出目录。

正例分别记录文件级 Recall@5、Recall@10、首个相关结果排名，并人工核对返回片段能否支持答案。近义问法、编号、英文与跨语言结果分别统计；不能只看总平均数。

无答案问题不以“向量检索返回空列表”为通过条件。向量搜索通常仍会返回近邻，回答层应确认资料没有支持证据并拒绝编造。数据库金额、订单号等用结构化查询验证，不用语义相似度推导精确数值。

这些合成样本用于演示和发现基本质量问题，不能证明真实业务资料的准确率、百万文件性能或跨平台兼容性。
