# v0.7.0 本地真实语义索引小样

记录日期：2026-10-06。原始指标见 [semantic-v0.7.0.json](semantic-v0.7.0.json)，复现入口为 [bench_semantic.py](../../scripts/bench_semantic.py)。

本次使用实际解析子进程、后台调度、ONNX CPU 推理和 ANN 构建子进程，没有用模拟向量替代模型。既有本地 BGE 模型通过固定 SHA-256 校验；没有下载模型、扫描用户资料或修改实际安装配置。

## 结果

|---|---:|---:|
| 首次全部正文就绪并通过关键词查询 | 2.292 秒 | 1.187 秒 |

这次小样中，首次正文与语义完成时间降低，ANN 构建进程启动次数减少，后端使用了更多内存。**单段修改没有表现出提速，ANN 更新成员数也没有减少。** 不能把首次建库的改善推广到所有增量场景。

两版修改后均完成了新关键词查询及新片段向量的 ANN 自查询。自然语言语义查询各返回 5 条结果，仅用于确认真实检索路径可用，没有评价相关性、排名或答案质量。

## 语料、配置与测量方式

- 合成资料共 24 个文件、260,019 字节，包含 UTF-8 TXT、GB18030 LOG、CSV、HTML、PDF、DOCX、XLSX、PPTX，每类 3 个。首次生成 258 个片段、194 个唯一文本向量。
- 使用 `Xenova/bge-small-zh-v1.5`，固定修订 `75c43b069aac4d136ba6bc1122f995fedcfd2781`，量化 ONNX、512 维，单模型进程、单推理线程。完整资产摘要在 JSON 中。
- 两版分别使用自己的新建配置默认资源设置：基线为 1 GiB／1 个解析进程／固定等待 50ms；候选为自适应上限 4 GiB／最多 4 个解析进程／无固定等待。两者解析进程的 Windows 内存限制均为 512 MiB，CPU 配置均为 25%。这不是资源条件完全相同的比较，也不代表旧安装会自动突破已有固定限制。
- 为隔离索引行为，关闭了自动忙碌、电池和前台查询等待策略，实际资源限制仍开启。后台扫描、真实模型及 ANN 调度均保持运行。
- 首次以 24 个文件均为 `ready`，并通过第一个文件的关键词查询作为正文完成条件；语义完成要求编码队列为空、最新 ANN 版本已发布且没有构建在进行。
- 增量仅修改第一个 TXT 的首段，随后显式请求一次核对；同时保留实际文件监控。因此结果不包含空闲扫描间隔，也不是操作系统文件事件延迟基准。
- 每版各运行一次，分开使用性能负载窗口，没有清空操作系统文件缓存。首次使用新解析／模型进程，增量阶段使用已加载的模型。
- 完成状态每 50ms 检查一次，RSS 每 25ms 采样，统计 Engine 及其子进程，不含 DSH 宿主、外部控制进程和语料生成。采样峰值可能遗漏短暂尖峰。

测试机器为 Windows、24 个逻辑 CPU、约 31.81 GiB 内存。此次 RSS 上升体现了并发任务的实际需求，不能据此要求插件占满配置上限或机器空闲内存。

## 源码与边界

- 基线完整提交：见 JSON 的 `baseline_commit`；源码摘要 `9d799b518cf45023a53882e4fdb0773d3088f90edb0668a291f47e05c5bb5536`。
- 候选源码摘要：`7a12255778b95272eed504bcd0786cca35b422b4351fed2923ce5c528f45fa9c`，与本轮最终正文基准的候选源码一致。
- 两版模型资产校验、两个阶段的检索检查均通过，测试后台线程均已结束。

这是短文档合成小样，不能外推到几百 GB 混合资料；没有测量物理 8GB 电脑、用户远程服务器、DSH 页面及 MCP 客户端全流程、断电恢复或多轮统计分布。局部文件修改也可能影响多个片段，不能承诺“改一个段落就只更新一个 ANN 成员”。

复现时使用已安装依赖和已有、匹配固定版本的本地模型，指定一个不存在的临时工作目录：

```powershell
.venv\Scripts\python.exe scripts\bench_semantic.py --work .packaging-smoke\semantic-rerun --model-dir .runtime\models\bge-small-zh-v1.5 --baseline 0cb03bb --files 24
```

脚本不会下载缺失模型；模型未就绪时记录跳过。原始运行目录仅用于本地诊断，公开 JSON 已去除绝对安装、语料和模型路径。
